# 가계부 앱 (moneylog-app) 개발 로드맵 v3 — 성능·운영·브랜딩 단계

> 마지막 업데이트: 2026-05-08
> 버전: v3.0 (이전: [v2.0 ROADMAP](./ROADMAP_v2.md), [v1.x ROADMAP](./ROADMAP.md))
> 기준 PRD: [PRD_v3.md](./PRD_v3.md)

---

## 프로젝트 개요

v2 사이클에서 10개의 신규 기능을 한꺼번에 얹은 후, 직접 사용해보니 첫 인상·응답 속도·정체성이 약점으로 드러났다. v3은 **의도적으로 신규 기능 0건**으로 두고 성능·운영·브랜딩 3개 트랙에 집중한 polishing 사이클이다. 마이그레이션 4개(`20260508_*`)는 모두 인덱스·트리거·RPC로 스키마 변경 없는 성능 개선.

---

## 성공 지표 (KPI)

- 통계 페이지 TTFB v2 대비 50% 단축
- 메모 페이지 이미지 전송 용량 60% 절감 (WebP)
- 홈 진입 → 첫 화면까지 1초 이내 (스플래시 제거)
- 모든 UI 라벨에서 "가계부" 문구 0건 (머니로그 정체성)
- v2 기능 회귀 0건

---

## 기술 스택 변경

**신규 라이브러리 없음.** 모든 작업은 기존 스택 위에서의 최적화·정비. PWA manifest 보강 외 외부 라이브러리 추가 없음.

## 리스크 및 학습한 점

| 항목 | 사전 예상 | 실제 결과·대응 |
|------|----------|---------------|
| 신규 기능 없는 사이클의 가치 증명 | "할 일이 없어 보일 수도" 우려 | TTFB·이미지 페이로드 등 정량 지표로 효과 확인 가능. 사용자 체감도 명확히 개선 |
| 스플래시 화면 제거 결정 | 한 번에 제거 vs 단계적 | 처음에는 서버/클라이언트 분리(`3f094a1`)로 절충 시도 → 결국 제거가 더 단순함을 깨달음(`ea94c63`). **절충안보다 본질 제거가 더 빠른 정답인 경우가 있음** |
| DB 인덱스 vs 쿼리 재작성 | 어디서 우선순위 둘지 | 두 트랙 병행. SSR prefetch는 클라이언트 raceL 해소, DB 인덱스는 절대 응답 시간 단축 |
| 브랜딩 변경 시 외부 영향 | URL·SEO 영향 우려 | 개인 프로젝트라 영향 미미. 다만 Google Play 등록명과 일관성 유지 필요 |
| LLM 도구 환경 부채 | CLAUDE.md 비대화 | 모듈화로 컨텍스트 토큰 절감. 디렉토리별 책임 분리가 LLM 가독성에도 도움 |
