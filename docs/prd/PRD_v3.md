# 가계부 앱 (moneylog-app) v3 PRD — 성능·운영·브랜딩 단계

> 마지막 업데이트: 2026-05-08
> 버전: v3.0 (이전: [v2.0 PRD](./PRD_v2.md), [v1.0 PRD](./PRD.md))

## 핵심 정보

**목적**: v2에서 확장된 기능 표면을 출시 가능한 품질로 끌어올린다. 새 기능 추가 대신 성능, 첫 인상, 브랜딩 정체성, 기술 부채를 한 사이클에 묶어 정리한다
**사용자**: v2와 동일. 다만 "처음 앱을 깔고 30초 안에 머무를지 결정하는 사용자" 관점을 우선

---

## v2 → v3 변경 요약 (회고)

v2에서 기능을 한꺼번에 늘리고 직접 써보니, **기능이 많아질수록 첫 로드 체감 속도가 무너지는 게** 가장 큰 문제였다. 통계 페이지에서 N+1 쿼리, 메모 이미지 페이로드 폭증, 차트 컴포넌트 리렌더링 폭주 등 v2 사이클에서 "일단 동작"으로 둔 부분들이 한꺼번에 드러났다.

또 하나의 자각은 **"가계부"라는 이름이 너무 평범해 정체성이 약하다**는 점이었다. 출시를 앞두고 프로젝트명을 `moneylog-app`으로 바꾸고 UI 라벨을 "머니로그"로 통일하면서 스플래시 화면처럼 의미 없는 진입 단계도 함께 제거했다.

v3은 의도적으로 **신규 기능 0건**으로 두고, 다음 3개 트랙에만 집중했다:

1. **성능**: SSR prefetch, DB 인덱스, 이미지 압축, 메모이제이션
2. **브랜딩**: 머니로그 정체성, 스플래시 제거, README/스토어 에셋
3. **기술 부채**: 미사용 폰트, 잔존 스플래시 코드, 스토어 에셋 위치 정리

## v1 라우트·테이블 변경 없음 (안정성)

v2에서 한 차례 통합한 통계 라우트(`/statistics/{income,expense}` → `/statistics`)는 v3에서 그대로 유지. 신규 테이블·신규 라우트는 없으며, 모든 변경은 **기존 구조 위에서의 최적화**다. 마이그레이션 4개(`20260508_*`)는 모두 인덱스·트리거·RPC로 스키마 변경 없음.

---

## 성공 지표 (v3 KPI)

- 통계 페이지 첫 응답(TTFB) v2 대비 50% 단축
- 메모 페이지 이미지 전송 용량 v2 대비 60% 절감 (WebP 압축)
- 홈 진입 → 첫 화면 표시까지 1초 이내 (스플래시 제거 효과)
- 머니로그 정체성 일관성 — 모든 UI 라벨에서 "가계부" 문구 0건
